# Data Model Specification

## 1. Purpose

Define persistent entities, fields, constraints, relationships, and migration requirements.

## 2. Database

| Item | Value |
|------|-------|
| Engine | PostgreSQL |
| Schema management | Flyway is solely responsible for schema creation and evolution |
| Hibernate | `spring.jpa.hibernate.ddl-auto=validate` |
| Identifier strategy | UUID primary keys generated by the application. PostgreSQL does not generate IDs |
| Optimistic locking | Out of scope for v1. Do not introduce `@Version` |
| Physical table names | Fixed: `tickets`, `comments` |

## 3. Enumerations

### Priority

| Value |
|-------|
| `LOW` |
| `MEDIUM` |
| `HIGH` |
| `CRITICAL` |

Default when omitted on create: `MEDIUM`.

### TicketStatus

| Value | Terminal |
|-------|----------|
| `OPEN` | No |
| `IN_PROGRESS` | No |
| `RESOLVED` | No |
| `CLOSED` | Yes |
| `CANCELLED` | Yes |

Initial status on create: `OPEN`.

Persistence: store enum values as strings (not ordinals).

## 4. Entity: Ticket

### Logical model

| Field | Type | Required | Constraints |
|-------|------|----------|-------------|
| id | UUID | Yes | Primary key; application-generated |
| title | String | Yes | Non-blank; max length 200 |
| description | String | Yes | Non-blank; max length 5000 |
| priority | Priority | Yes | One of enum values; default `MEDIUM` |
| status | TicketStatus | Yes | One of enum values; initial `OPEN` |
| assignee | String | No | Max length 100; null allowed |
| createdAt | Instant (timestamptz) | Yes | Set on insert; immutable thereafter |
| updatedAt | Instant (timestamptz) | Yes | Set on insert; updated on every successful ticket mutation |

### Ticket mutations that update `updatedAt`

- Successful PATCH of ticket fields
- Successful status transition
- Successful addition of a comment (parent ticket `updatedAt` is refreshed)

### Forbidden client fields on create and PATCH

| Situation | Behavior |
|-----------|----------|
| `status` present on create | HTTP 400, `BAD_REQUEST`; no ticket created |
| `status` present on PATCH | HTTP 400, `BAD_REQUEST`; ticket unchanged |
| `id`, `createdAt`, or `updatedAt` present on create | HTTP 400, `BAD_REQUEST`; no ticket created |
| `id`, `createdAt`, or `updatedAt` present on PATCH | HTTP 400, `BAD_REQUEST`; ticket unchanged |
| Unknown JSON fields on create | HTTP 400, `BAD_REQUEST`; no ticket created |
| Unknown JSON fields on PATCH | HTTP 400, `BAD_REQUEST`; ticket unchanged |

## 5. Entity: Comment

### Logical model

| Field | Type | Required | Constraints |
|-------|------|----------|-------------|
| id | UUID | Yes | Primary key; application-generated |
| ticketId | UUID | Yes | Foreign key → `tickets.id` |
| author | String | Yes | Trimmed non-blank; max length 100 |
| content | String | Yes | Trimmed non-blank; max length 2000 |
| createdAt | Instant (timestamptz) | Yes | Set on insert; immutable |

### Relationship

- Many comments belong to one ticket (`comments.ticket_id` → `tickets.id`).
- Deleting tickets is out of scope for v1; no application delete API.
- Foreign key on `comments.ticket_id` uses `ON DELETE RESTRICT`.

## 6. Validation Rules (domain / API)

### Blankness

- “Non-blank” means: not null, not empty, and not whitespace-only.
- Fields `title`, `description`, `assignee`, `author`, and `content` are trimmed, then validated as non-blank where required.

### Ticket create

| Field | Rule |
|-------|------|
| title | Required; trimmed non-blank; max 200 |
| description | Required; trimmed non-blank; max 5000 |
| priority | Optional; if present must be valid enum; if omitted defaults to `MEDIUM` |
| assignee | Optional; if present max 100; empty/whitespace-only after trim stored as null |
| status | Must not be present; if present → HTTP 400 `BAD_REQUEST`; no ticket created |

### Ticket PATCH

| Field | Rule |
|-------|------|
| title | If present: trimmed non-blank; max 200 |
| description | If present: trimmed non-blank; max 5000 |
| priority | If present: valid enum |
| assignee | If present: max 100; empty/whitespace-only after trim clears to null |
| status | If present: HTTP 400 `BAD_REQUEST`; ticket unchanged |
| Unknown fields | HTTP 400 `BAD_REQUEST`; ticket unchanged |

### Comment create

| Field | Rule |
|-------|------|
| author | Required; trimmed non-blank; max 100 |
| content | Required; trimmed non-blank; max 2000 |
| Unknown fields | HTTP 400 `BAD_REQUEST`; no comment created |

## 7. Indexes (required)

| Index | Purpose |
|-------|---------|
| Primary key on `tickets(id)` | Lookup |
| Primary key on `comments(id)` | Lookup |
| Index on `comments(ticket_id)` | Load comments for ticket |
| Index on `tickets(status)` | Status filter |

Search uses PostgreSQL case-insensitive substring matching (`ILIKE`) against `title` and `description`. No full-text search index is required in v1. No Elasticsearch.

## 9. What Is Not Stored (v1)

- User accounts
- Transition / audit history rows
- Attachments
- Tenant identifiers
- Soft-delete flags
- Version / optimistic-lock columns
