# Documentation Skill

When documenting a feature:

1. Explain the problem.
2. Explain the design.
3. Explain important decisions.
4. Explain API behavior.
5. Explain validation rules.
6. Explain failure cases.
7. Explain testing strategy.

Documentation must describe actual implemented behavior.

Never claim a feature works without evidence from tests or manual verification.

When implementation differs from specification:

1. identify the discrepancy
2. explain why
3. update the relevant artifact
4. document the decision
